週報の下書きを作る。対象: $ARGUMENTS

ゼミでは週2回発表する（ユーザーの説明、2026-09-27）:
- **月曜**: 先週の振り返り ＋ 今週の todo → Issue の上半分（先週からの持ち越し／今週の目標／金曜日に確認できる成果物／今週の主な活動／懸念・障害・相談事項）
- **金曜**: 今週の成果・反省・来週以降の方針 → Issue の下半分（完了したこと／完了しなかったこと／当初の計画から変更したこと／分かったこと・得られた知見／成果物・Evidence／次週への課題）

材料を集める:
- `git log --since=<前回の発表日>` （Evidence の Commits 欄に短縮ハッシュ＋1行説明。リンクは https://github.com/takakuwa-mamada/squat-rpe-research/commit/<hash>）
- `CLAUDE.md` の §3 現在地・§8 次にやること、`docs/研究コンテキスト.md` §10 の過去の目標
- `python scripts\run_pipeline.py --report-only` の被験者ごとの試技数・RPE 分布・要確認

書き方:
- 見出しは `docs/研究コンテキスト.md` §10 のテンプレート（2026-09 以降の形式）をそのまま使う。ユーザーがテンプレートを貼ったらそれに合わせる。
- 事実だけを書く。やっていないことを書かない。数値はファイルから取る。n が小さい結果は参考値と書く。
- 月曜: 先週の目標それぞれの達成状況（持ち越し）を書き、今週の目標は3つ、金曜に確認できる形（数と成果物）で書く。
- 金曜: 月曜に立てた目標ごとに完了／未完了を書き、次週への課題は来週月曜の目標の候補になる形で書く。
- 「ゼミ出欠」「欠席時の連絡・相談」「振り返り（うまくいったこと／難しかったこと／改善したいこと）」はユーザーが書くので空欄で残す。
- Issue 全体を、コピペしやすい1つのコードブロックで出す。
- 目標が確定したら `docs/研究コンテキスト.md` §10 の「これまでの目標」に追記する。
