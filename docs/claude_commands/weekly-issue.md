argument-hint: [monday | friday]  省略時は曜日で判断（月〜木 = その週の monday、金 = その週の friday、土・日 = 次の週の monday）

週報を一から書く（ユーザーがテンプレートを貼らなくてよい）。対象: $ARGUMENTS

ゼミでは週2回発表する（ユーザーの説明、2026-09-27）:
- **月曜**: 先週の振り返り ＋ 今週の todo → Issue の上半分「Monday — Plan」（先週からの持ち越し／今週の目標／金曜日に確認できる成果物／今週の主な活動／懸念・障害・相談事項）
- **金曜**: 今週の成果・反省・来週以降の方針 → Issue の下半分「Friday — Result」（完了したこと／完了しなかったこと／当初の計画から変更したこと／分かったこと・得られた知見／成果物・Evidence／次週への課題）

**鉄則（ユーザー指示、2026-10-31）: 金曜の部分は、その週の月曜より前に書かない。月曜より前に進んだ作業も、結果は金曜に発表する。**
月曜の下書きでは「Friday — Result」を雛形のまま空欄で残す。月曜の部分にも結果（数値・済んだこと）は書かず、計画・相談として書く。

手順:
1. Issue は前週の金曜に YokoyamaLab/Masaki-Takakuwa に自動で作られる（タイトル「[M1 高鍬] [進捗報告] <その週の月曜の日付>」）。
   `gh issue list --repo YokoyamaLab/Masaki-Takakuwa --state all --limit 3` で番号を確かめ、`gh issue view <番号> --repo YokoyamaLab/Masaki-Takakuwa` で今の本文を読む。
   ユーザーが書き込んだ部分は消さずに残す（直したほうがよい点はコードブロックの後で伝える）。
   本文が読めないときは雛形 `docs/claude_commands/weekly_issue_template.md`（研究室の YokoyamaLab/Lab_Management `templates/weekly-progress.ja.md` の写し）を使う。
   見出し・チェックボックス・研究室の説明文の文言は変えない。Week はその週の月曜の日付。
2. 材料を集める:
   - 前週の Issue の「完了しなかったこと」「次週への課題」（月曜の「先週からの持ち越し」の材料。Previous issue: に前週の番号を書く）
   - `git log --since="<前回のゼミの金曜>T12:50:00+09:00" --format="%h %ad %s"`（金曜の Commits 欄。研究室の集計は金曜 12:50 JST 〜 次の金曜 12:50 JST。
     短縮ハッシュ＋日本語1行。リンクは https://github.com/takakuwa-mamada/squat-rpe-research/commit/<hash>）
   - `CLAUDE.md` の §3 現在地・§8 次にやること、`docs/研究コンテキスト.md` §10 の「これまでの目標」
   - `python scripts\run_pipeline.py --report-only`（被験者ごとのセッション数・試技数・RPE 分布・要確認）
3. リポジトリから分からないこと（ジムで計測したか、先生との相談の結果、ゼミ以外の予定、協力者の反応など）は、
   下書きの前に AskUserQuestion で最大3問だけ聞く。聞かずに推測で埋めない。
4. Issue 全体を埋めて、コピペしやすい1つのコードブロックで出す。
   - 月曜: 前週の目標それぞれの達成状況（前週の金曜のゼミの時点）を「先週からの持ち越し」に書く。今週の目標は3つ、金曜に確認できる形（数と成果物）で書く。
     前週のゼミの後に進んだ作業の結果は金曜に回す（必要なら今週の目標・成果物に入れる）。下半分は空欄のまま。
   - 金曜: 上半分は月曜に出したもの（Issue の本文）を使う。月曜の目標ごとに完了／未完了を書き、次週への課題は来週月曜の目標の候補になる形で書く。
5. コードブロックの後に、判断が要る点（目標の妥当性、載せ方を迷った項目）を3行以内で添える。

書き方:
- 研究室の、この分野を知らない人にも伝わるように書く。専門用語は使ってよいが、初めて出るところで短く意味を添える
  （例: RPE（主観的なきつさ。10 = 限界、9 = あと 1 回できた）、IMU（バーに付けた加速度センサ）、MCV（上がる局面の平均速度）、
  速度低下（1 回目から最後の回までに速度が何 % 落ちたか）、95 % 一致限界（レップごとの差の 95 % が入る範囲））。
- 造語をしない。スクリプトの中の呼び名（足元切れ・横切り・要確認・margin・BL など）はそのまま使わず、一般的な言い方にする。
- 事実だけを書く。やっていないことを書かない。数値はファイルから取る。n が小さい結果は参考値と書く。
- 「ゼミ出欠」「欠席時の連絡・相談」「振り返り（うまくいったこと／難しかったこと／改善したいこと）」はユーザーが書くので空欄で残す。
- 協力者の名前は出さない（S002〜 の被験者ID で書く）。Artifact のリンクは共有設定が必要なので載せず、リポジトリ内のファイル名を書く。
- GitHub には投稿しない（下書きだけ。Issue への書き込みはユーザーが行う）。
- 目標が確定したら `docs/研究コンテキスト.md` §10 の「これまでの目標」に追記する。
