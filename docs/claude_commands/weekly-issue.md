週報を一から書く（ユーザーがテンプレートを貼らなくてよい）。対象: $ARGUMENTS

ゼミでは週2回発表する（ユーザーの説明、2026-09-27）:
- **月曜**: 先週の振り返り ＋ 今週の todo → Issue の上半分（先週からの持ち越し／今週の目標／金曜日に確認できる成果物／今週の主な活動／懸念・障害・相談事項）
- **金曜**: 今週の成果・反省・来週以降の方針 → Issue の下半分（完了したこと／完了しなかったこと／当初の計画から変更したこと／分かったこと・得られた知見／成果物・Evidence／次週への課題）

手順:
1. 雛形は `docs/claude_commands/weekly_issue_template.md`（研究室の Issue フォームそのまま）。見出し・チェックボックスの文言は変えない。
   Week は今週の月曜の日付。ユーザーが別の形式を貼ったらそちらに合わせる。
2. 材料を集める:
   - `git log --since=<前回の発表日> --format="%h %ad %s"`（Commits 欄に短縮ハッシュ＋日本語1行。リンクは https://github.com/takakuwa-mamada/squat-rpe-research/commit/<hash>）
   - `CLAUDE.md` の §3 現在地・§8 次にやること、`docs/研究コンテキスト.md` §10 の「これまでの目標」（先週の目標・前回の下書き）
   - `python scripts\run_pipeline.py --report-only`（被験者ごとのセッション数・試技数・RPE 分布・要確認）
   - 前回の週報の下書きが会話に残っていればそれも
3. リポジトリから分からないこと（ジムで計測したか、先生との相談の結果、ゼミ以外の予定、協力者の反応など）は、
   下書きの前に AskUserQuestion で最大3問だけ聞く。聞かずに推測で埋めない。
4. Issue 全体を埋めて、コピペしやすい1つのコードブロックで出す。
   - 月曜: 先週の目標それぞれの達成状況を「先週からの持ち越し」に書く。今週の目標は3つ、金曜に確認できる形（数と成果物）で書く。
     下半分（金曜日時点の結果）は空欄のまま、または前週末に済ませた作業があれば「（◯/◯ 実施）」と明記して入れる。
   - 金曜: 上半分は月曜に出したものを使う（会話か §10 から）。月曜の目標ごとに完了／未完了を書き、次週への課題は来週月曜の目標の候補になる形で書く。
5. コードブロックの後に、判断が要る点（目標の妥当性、載せ方を迷った項目）を3行以内で添える。

書き方:
- 事実だけを書く。やっていないことを書かない。数値はファイルから取る。n が小さい結果は参考値と書く。
- 「ゼミ出欠」「欠席時の連絡・相談」「振り返り（うまくいったこと／難しかったこと／改善したいこと）」はユーザーが書くので空欄で残す。
- 協力者の名前は出さない（S002〜 の被験者ID で書く）。Artifact のリンクは共有設定が必要なので載せず、リポジトリ内のファイル名を書く。
- 目標が確定したら `docs/研究コンテキスト.md` §10 の「これまでの目標」に追記する。
