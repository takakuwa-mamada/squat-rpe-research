## 1. 研究の全体像

### 1.1 題目の変遷

| 時期 | 資料 | 題目 |
|---|---|---|
| 2026-07 | 中間発表ポスター（A0 縦1列） | レジスタンストレーニングにおける単眼動画の骨格推定とバーベル挙上速度を用いたRPE推定とその妥当性検証 |
| 2026-08 | 外部向け発表（3枚） | バーベルトレーニングにおける主観的運動強度(RPE)の推定 |
| 2026-08〜09 | 研究計画書 | マルチモーダルセンシングによるバーベルトレーニングの主観的運動強度推定 — 個人適応型モデルの構築に向けた研究計画 — |

### 1.2 背景と課題

- **RPE**（Zourdos 2016 の RIR ベース）: 「あと何回挙がるか」で強度を数値化する。簡便で現場で広く使われるが、
  主観なので個人差・経験差が大きく、その日のコンディションで申告がぶれ、申告が妥当だったかを後から確かめる手段がない。
- **VBT**: 平均推進速度（MPV）と %1RM に強い線形関係がある（González-Badillo 2010、R² = 0.98）。
  セット内の速度低下率は血中乳酸・アンモニアと強く相関する（Sánchez-Medina 2011、r = 0.93）。
  ただしバーの並進という単一の情報しか使わず、疲労に伴うフォームの崩れ（体幹前傾の増大、膝の内側変位など）を捉えられない。

### 1.3 目的

客観的なセンサデータから RPE を推定し、

1. アスリート自身の RPE 申告を補助する
2. 疲労管理の精度を上げる
3. 疲労に伴う動作の質的変化（フォーム）を可視化する

外向きには「パワーリフティング」を前面に出さず、**アスリートがバーベル種目でよく使う指標** として RPE を説明する（ユーザー方針、2026-08-04）。

### 1.4 位置づけ（自動化のレベル）

| レベル | 内容 | 例 |
|---|---|---|
| Lv1 | 速度を計測・表示する | 一般的な VBT 機器 |
| Lv2 | 速度を使って判断を支援する（RPE の判断は人間） | Stance など |
| Lv3 | センサから RPE を自動推定する | 市販品は見当たらない（2026-08 時点の調査）。研究では IMU+EMG（arXiv:2510.03197）、等速性ベンチの力-時間データで RF・±1 RPE 以内 93% 以上（Sensors 2025, 25(21), 6588）など。いずれも EMG 電極や専用装置が前提で現場運用に向かない |

本研究は **現場で運用できる計測（バー IMU＋スマホ動画）だけで Lv3** を狙い、しかも **個人適応型** にする点が違い。

### 1.5 最終目標と修論のスコープ

- 最終目標（修論の外）: スマホの単眼動画だけで骨格推定・挙上速度・RPE 推定・フォーム分析を行うアプリ。「Stance を超えるアプリ」。
- それを直接ゴールにすると「センサーいらなくね？」となる問題（2026-08 にユーザーが提起）への答え:
  **IMU は製品ではなく、動画由来の特徴量を検証する基準（教師）**。修論では
  (1) マルチモーダルで RPE 推定が良くなること、(2) 単眼動画の関節角・バー速度が IMU 基準でどこまで妥当か、
  (3) 個人モデルに必要な試技数、を示す。これが将来「動画だけ」に移行する根拠になる。
- ユーザーが描いた大きな目標: IMU をバー・両膝・両肘・体幹などに付け、同時に動画で骨格推定し、
  **個人のデータだけで** フォーム学習・分析と、挙上速度の傾向からの RPE 推定を行う。
- 2027-02 の修論中間審査で最低限示したいこと: **マルチモーダルの優位性**（IMU のみ vs IMU＋骨格、同一被験者内 LOSessionO）。

### 1.6 研究課題（暫定）

- RQ1: IMU＋骨格のマルチモーダル特徴は、速度のみ（VBT/Stance 相当）より RPE を正確に推定できるか。
- RQ2: 単眼動画から得た関節角・バー速度は、IMU を基準としてどの程度妥当か（特にバーベルの遮蔽局面）。
- RQ3: 個人適応型モデルは何試技・何セッションで実用水準（±1 RPE）に達するか。

### 1.7 想定される限界

- 個人モデルのコールドスタート（データが貯まるまで使えない）。
- 正解ラベルの RPE 自体が主観。モデルは「本人が申告するであろう RPE」を推定する。
- 種目はバックスクワットのみ。
- 被験者が研究者本人 → 申告バイアスの危険。RPE 記録ルール（§6.2）で対策する。

## 5. ソフトウェア詳細

### 5.1 IMU 特徴量（`extract_features.compute_imu_features`）

- 前処理: `az_dyn = (az − 1)·g` → Butterworth 4次 LPF 10 Hz（filtfilt）→ 台形積分で速度 → 3 s 超なら 2次 HPF 0.3 Hz、短ければ平均除去。
- 19 特徴: `n_samples, fs_hz, total_time_s, concentric_time_s (v>0.05), eccentric_time_s (v<−0.05), peak/mean_velocity_up/down, n_reps_detected, first/last/mean_rep_peak_v, velocity_loss_pct, rms_accel, peak_accel, max/mean_jerk, bar_roll/pitch_range_deg`。
- `detect_reps`: 上昇閾値 max(0.12, 0.30·vmax)、下降閾値 max(0.08, 0.20·vmax)、ピーク間隔 0.6 s 以上、
  直前 3 s に下降があるピークだけ採用（ラックアウトの歩き出しを除外）、meta の reps_completed（なければ reps_planned）があれば速度上位 N 個に制限。
- 限界: 姿勢補正なし、MCV/MPV なし、roll/pitch はドリフト込み（CLAUDE.md §7）。

### 5.2 骨格（`pose_extract_yolo.py`）

- YOLO26m-pose（`weights/yolo26m-pose.pt`、無ければ自動ダウンロード名）、conf 0.25、GPU 自動。17 点（COCO）。
- フレーム特徴: 膝角 = hip–knee–ankle、股角 = shoulder–hip–knee、trunk_lean = 肩中点→腰中点ベクトルの鉛直からの角度、
  hip_y = 腰中点の y、knee_forward_x = 膝中点 x − 足首中点 x、asymmetry_knee = |左膝角 − 右膝角|、key_visibility = 主要8点の conf 平均。
- 出力: `_yolo_keypoints.csv`、`_yolo_features.csv`、`_yolo_annotated.mp4`、`_yolo_plots.png`。
- 注意: これらは 2D 画像上の角度。撮影方向に依存する（正面動画では屈曲角・前傾は妥当でない）。

### 5.3 バー軌道（`bar_path_extract.py` + `bar_tracking.py`）

- プレート円の決定: `--roi` 手動 → 保存済み `<stem>_bar_roi.json` → Hough 円＋エッジ支持率で自動検出（先頭 10 s を 0.2 s 刻みで探索）→ 失敗時のみ GUI。
- 追跡: CSRT → Hough 円で補正（ずれが半径の 0.35 倍超で再初期化）→ ロスト時はテンプレートで再取得。
- スケール: Hough 半径の中央値とプレート直径 450 mm で mm/px。Savitzky–Golay で平滑化・微分して速度。ROM 150 mm 以上をレップとして、コンセントリックの平均・ピーク速度を算出。
- 側面撮影が前提（正面からはプレートが円に見えない）。SES004 では未実行。

### 5.4 学習（`train_rpe_model.py`）

- 入力 `outputs/features_all.csv`。数値列を自動選択（メタ列・全 NaN・定数列を除外）。NaN を含む行は落とす。
- モデル: linear（StandardScaler＋LinearRegression、`imu_first_rep_peak_v_mps` のみ）、rf（200本、深さ8）、gb（200本、深さ3、lr 0.05）。
- CV: 被験者2名以上 → LOSO、1名 → 5-fold（シャッフル）、5件未満 → train のみ。指標: MAE、RMSE、±0.5 / ±1.0 以内率。
- 出力 `models/<日時>/`: `linear.pkl` 等、`metrics.json`、`feature_columns.json`、`predictions.csv`、`scatter_*.png`、`importance_*.png`。
  （冒頭 docstring のファイル名は古い）
- 改修予定: LOSessionO、アブレーション、学習曲線、除外列リスト（CLAUDE.md §7-10）。

## 6. 計測プロトコル

### 6.1 当日の流れ（`docs/計測チェックリスト` の要約）

1. 持ち物: M5（充電済み）＋固定バンド、ノート PC、スマホ＋三脚、テザリング（2.4 GHz）、養生テープ。
2. セットアップ: テザリング ON → PC 接続 → `ipconfig` で IP 確認 → M5 をシャフト中央に（画面が真上）→ `multi_imu_receiver.py` 起動 →
   受信リストに BAR → **バー水平で az ≈ 1.0 g を確認** → 三脚は 2.5〜3 m・腰の高さ、プレート全体とラック支柱2本が画角に入る → 三脚位置にテープ。
3. 各セット（記録セットのみ）: 重量セット → 録画開始 → SPACE → 挙上 → SPACE → **RPE を声に出す（画面を見る前）** → 数字キー → 録画停止。
   マーカーはおおまかでよい（歩く時間が入っても後処理でレップを検出する）。
4. 終了後: q → mean Hz 90〜100 → セット数 → RPE 未入力なし → 記録ログ（睡眠・体重・体調・前回からの間隔）。
5. 初回は3セット程度で通してから本数を増やす。

※ 動画の撮り方（セットごと vs 回しっぱなし）は資料間で不一致。CLAUDE.md §7-12 と §8 P0-3。

### 6.2 RPE 記録ルール

- 挙上直後 15 秒以内に、口に出して言ってから記録する。
- PC の画面（速度の数値）を見る前に決める。見てから決めるとラベルが汚染される。
- 一度記録した値は後から変更しない（中間値 8.5 などの入力のための編集は可）。
- 理由: 本人が被験者なので、無意識に「当てやすい値」を申告してしまう危険がある。

### 6.3 計測メニュー（`docs/スクワット計測メニュー.xlsx`）

設定シートに 1RM・バー重量 20 kg・刻み 2.5 kg を入れると各セットの重量とプレート内訳が出る（`=ROUND(1RM×%/2.5,0)×2.5`）。
記録ログシートあり。週3回なら A → B → C の順で回す。疲労が抜けなければ頻度を落とす。

**A ヘビー**（狙う RPE 7〜10、記録6セット、約60分）

- W-up: バー×10（1分）, 40%×5（1分）, 55%×3（2分）, 65%×3（2分）, 75%×2（3分）
- 記録: 85%×3（3分, RPE 7-8）→ 88%×2（3分, 8）→ 91%×1（4分, 8-9）→ 94%×1（4分, 9）→ 88%×2（3分, 9）→ 85%×3（—, 9-10）

**B ミディアム**（狙う RPE 6〜10、記録8セット、約60分）

- W-up: バー×10（1分）, 40%×5（1分）, 55%×3（2分）, 65%×3（2分）
- 記録: 72.5%×5（2分, 6-7）→ 77.5%×5（3分, 7）→ 82.5%×3（3分, 7-8）→ 85%×3（3分, 8）→ 87.5%×2（3分, 8-9）→ 82.5%×4（3分, 9）→ 77.5%×5（3分, 9）→ 72.5%×6（—, 9-10）

**C ボリューム**（狙う RPE 6〜10、記録8セット、約55分）

- W-up: バー×10（1分）, 40%×5（1分）, 55%×5（2分）
- 記録: 65%×8（2分, 6）→ 70%×6（2分, 6-7）→ 72.5%×6（3分, 7）→ 75%×5（3分, 7-8）→ 72.5%×6（3分, 8）→ 70%×7（3分, 8-9）→ 67.5%×8（3分, 9）→ 65%×8（—, 9-10）

括弧内は（休息, 目安 RPE）。目安はあくまで予想で、**実際の申告は正直に**。

### 6.4 同期方式（決定済み・未実装）

- ラックイン: バーをラックに置く瞬間、IMU に鋭い減速ピーク（3〜5 g）、動画に「ガシャン」という音。ラックアウトにも小さいが明確な衝撃。
- 毎セット2点の同期信号。セット間隔のパターン照合で誤検出に強い。
- 処理案（`sync_align.py`）: ffmpeg で音声抽出 → オンセット検出 → IMU az の衝撃検出 → パターン照合でオフセット →
  始点・終点の2点でクロックずれを線形補正 → markers.csv と合わせて動画をセット単位に分割。
- 予備: IMU 積分の鉛直位置と `bar_path_extract` のプレート軌跡の相互相関（ジムの音楽で音が使えない場合）。
- 回しっぱなし録画なら全体で1回オフセットを決めればよい。セットごと録画でも各動画にラックアウトとラックインが入っていれば同期できる。

## 11. 用語

| 用語 | 意味 |
|---|---|
| RPE | Rating of Perceived Exertion。ここでは RIR ベースの 1〜10（10=限界） |
| RIR | Repetitions in Reserve。あと何回挙がるか |
| 1RM / %1RM | 1回だけ挙がる最大重量 / それに対する割合 |
| VBT | Velocity-Based Training。挙上速度で負荷や疲労を管理する方法 |
| MCV / MPV | 平均コンセントリック速度 / 平均推進速度（減速局面を除いた平均） |
| VL | Velocity Loss。セット内の速度低下率 =（初回 − 最終）/ 初回 |
| LRV | Last Rep Velocity。最終レップ速度から RPE を推定する方法 |
| LOSO / LOSessionO | Leave-One-Subject-Out / Leave-One-Session-Out 交差検証 |
| ROM | 可動域（Range of Motion） |
| Bland–Altman | 2つの計測法の一致度を差と平均で評価する方法 |
| IMU | 慣性計測装置（加速度＋角速度） |
| COCO 17 点 | YOLO 系の骨格キーポイント定義（足先なし） |
| ラックアウト / ラックイン | バーをラックから外す / 戻す動作 |
