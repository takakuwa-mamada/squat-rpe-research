 スクワット計測 チートシート（正面撮影・1セット＝動画1本）
=============================================================

■ 出発前に1回だけ
-------------------------------------------------------------
 firmware\m5stick_multi_sender\m5stick_multi_sender.ino（v4）の
 WIFI_LIST にスマホのテザリングを追加（pc_ip は "" でOK）
 → Arduino IDE で書き込み（M5Stick-C-Plus / COM3 / 1500000）


■ ジムで（本人: IMU＋動画）
-------------------------------------------------------------
 1. テザリングON → PC接続
 2. python scripts\multi_imu_receiver.py
    → 「重量 回数」を入力（例: 90 3）。ジム1回につき起動は1回だけ（横から撮るセットは別。下）
    → 重量・回数が変わるセットの前に グラフ画面で w → ターミナルで入力
 3. M5電源ON → 画面が「PC:xx.xx.xx.xx A」（緑）になればOK
 4. M5 をバーの端（プレートの外側・動画で右側）に、毎回同じ位置
    画面が真上 → バー水平で az ≒ 1.0
                                     ★ここ外すと全部無駄
 5. スマホ: 正面・2.5〜3 m・腰の高さ・縦向き・三脚
            頭から足先まで全身（しゃがんでも切れない）
 6. 各セット:
      録画開始 → SPACE → ラックアウト→挙上→ラックイン → SPACE
      → RPEを声に出す（画面を見る前）→ 数字キー → 録画停止
 7. q で終了 → mean Hz が 90〜100 か確認

 キー:  SPACE=セット区切り   6〜9=RPE   0=RPE10   5=RPE5
        w=次の重量・回数    u=直前を取消        q=終了


■ 横から撮るセット（IMU が正しいかの確認用。アップでよい）
-------------------------------------------------------------
 合計 6 セット（1 セット 3〜5 回）。できれば 2 日に分けて 3 セットずつ
 1. 本番の前に、受信を別のフォルダで起動（いつもの取り込みに混ざらない）
      python scripts\multi_imu_receiver.py --outdir data\_side
 2. スマホ: M5 を付けた側（自分の左）の真横。プレートがまん丸に見える位置
            腰の高さ・2.5〜3 m・縦向き・三脚
            プレートが上から下まで切れない・ラックやセーフティバーで隠れない
            （最初の1本で確認）
 3. いちばん外側が 20 kg プレート（直径 45 cm）になる重さで（60 kg か 100 kg。
    外に小さいプレートを足さない。プレートの直径を物差しにするため）
 4. 各セット: 録画開始 → SPACE → ラックアウト→挙上→ラックイン → SPACE → 録画停止
    RPE は入れない
 5. q で終了 → 本番はいつもどおり python scripts\multi_imu_receiver.py
 帰宅後: 動画は data\_side\session_…\ の直下へ（ファイル名の順 = セットの順。
         run_pipeline.py では取り込まない）
      python scripts\compare_side_imu.py      ← プレートと IMU の速度を比べる
   → 最後の「判定」に、横の動画 ÷ IMU の倍率と、どちらがずれているかが出る
   → プレートを正しく見つけたかは data\_side\session_…\plate\*_bar_roi_preview.png
     （緑の円がプレートの縁に重なっていれば OK）


■ 帰宅後（本人）
-------------------------------------------------------------
 1. 動画をスマホから、その日の data\_sessions\session_…\ の直下へコピー
    （受信を何回か起動した日は、フォルダごとにそのセットの動画を入れる）

 2. cd "G:\マイドライブ\大学院\M1\Projects\Research"
    python scripts\run_pipeline.py
    → 新しい計測を日ごとに自動で SES 番号をつけて取り込み → 骨格推定 → 特徴量 → 品質レポート
    → [待ち] と出たら、そのフォルダに動画が入っていない。入れてからもう一度
    → 最後の「品質レポート」で 要確認 が出たらそこを直す

 （SES 番号を自分で決めたいときだけ: python scripts\split_session.py --session SES004 --src …）


■ 仲間の動画（LINE で受け取る）
-------------------------------------------------------------
 1. LINE の動画を data\_remote\<名前>\<撮った日>\ に保存（例 data\_remote\<名前>\20261105\）
    名前は「撮った順の番号_動画の次に送られてきた1行」→ 01_100kg 5回 RPE8.mp4
    ・LINE の動画は保存期間が過ぎると開けなくなるので、届いたら早めに
    ・初回だけ、送られてきた4行（身長・体重・1RM・歴）を data\_remote\<名前>\プロフィール.txt に貼る
 2. python scripts\ingest_remote.py --dry-run    ← 並び順とラベルを確認（コピーしない）
 3. python scripts\ingest_remote.py
 4. python scripts\run_pipeline.py
   → [要確認] が出た人には LINE で聞く（ラベル抜け・足元切れ など）


■ データがたまったら
-------------------------------------------------------------
 python scripts\train_rpe_model.py
   → models\<日時>\report.md に比較表・学習曲線・重要度


■ よくあるやつ
-------------------------------------------------------------
 PC: が黄色のまま     → 受信スクリプトが動いているか / ファイアウォールで Python を許可
 mean Hz < 50         → PC をラックに近づける
 足元が切れている     → カメラを下げる or 離す
 正面から撮れていない → カメラをバーベルの真正面へ
 RPE 8.5 にしたい     → meta.json を直接編集（split_session を再実行しても残る）
 コードを直した       → python scripts\run_pipeline.py --force-features
