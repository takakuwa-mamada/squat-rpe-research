================================================================================
  計測後のデータ処理手順
================================================================================
  ジムから帰ってきた後、データを解析できる形にするまでの手順。
  すべて PowerShell で実行する。

  最初に必ずこれを実行（作業フォルダへ移動）:

      cd "C:\Users\129ka\OneDrive\ドキュメント\Claude\Projects\大学院研究"

  以降のコマンドは、このフォルダにいる前提で書いてある。

================================================================================
 0. 計測直後のデータの場所
================================================================================

  受信スクリプトを終了すると、以下に生データが保存されている。

      data\_sessions\session_YYYYMMDD_HHMMSS\
          raw_BAR.csv          … IMUの連続データ
          markers.csv          … セット区切りとRPE
          session_info.json    … 受信統計（サンプル数・実効Hz）

  動画はスマホからPCへ移し、このセッションフォルダに入れておく。
  ファイル名は何でもよい（例: 130.mp4）。

--------------------------------------------------------------------------------
 【近道】とりあえず骨格推定だけ試したいとき
--------------------------------------------------------------------------------

  正式な構造に変換しなくても、動画をセッションフォルダに置くだけで動く。

      python scripts\pose_extract_yolo.py --subject _sessions

  → data\_sessions\session_◯◯◯\pose\ に結果が出る。
    （videos\ フォルダは作らなくてよい）

  骨格がちゃんと取れているか確認したいだけなら、ここで止めてよい。
  フル解析に進む場合は、次の【1】から順に進める。

================================================================================
 1. セッションをセット単位に分割する
================================================================================

  生データのままでは特徴量抽出ができないので、
  data\<被験者>\<セッション>\ の構造に変換する。

  ■ 最新のセッションを変換する場合

      python scripts\split_session.py --subject S001 --session SES004

  ■ セッションを指定する場合（複数ある / 古いものを処理したい）

      python scripts\split_session.py --src data\_sessions\session_20260918_004509 --subject S001 --session SES004

  --session には既存と重複しない番号を指定する。
  今 data\S001\ に何があるかは以下で確認できる。

      dir data\S001

  実行すると、こう表示される:

      [SRC] ...\data\_sessions\session_20260918_004509
      [MARKERS] 1 セット
        [LOAD] BAR          4618 samples  (0.0s 〜 46.2s)
        SET  1     5.5s  1 devices  RPE=7.0
      [OK] ...\data\S001\SES004
           imu/     : 1 ファイル
           meta.json: 1 セット

  ※ 1回のジムセッションで受信スクリプトを起動し直した場合、
    セッションフォルダが複数に分かれる。その場合は
    --session を SES004, SES005, SES006 … と分けて実行する。
    （本来は1回起動したまま全セットを記録するのが望ましい）

================================================================================
 2. 動画を配置する
================================================================================

  分割時に videos\ フォルダが自動で作られている。
  そこへ動画を set01.mp4, set02.mp4 … という名前で置く。

      data\S001\SES004\videos\set01.mp4

  セット番号と動画を必ず対応させること。
  （meta.json の video_filename と一致している必要がある）

================================================================================
 3. meta.json に重量とレップ数を追記する
================================================================================

  メモ帳などで開く:

      notepad data\S001\SES004\meta.json

  null になっている箇所を埋める:

      "weight_kg": 130,          ← 実際に挙げた重量
      "reps_planned": 3,
      "reps_completed": 3,
      "rest_before_sec": 180,

  RPE は計測時に入力済みなので、通常は触らなくてよい。
  RPE 8.5 など中間値を入れたい場合はここで修正する。

  ※ 予定と違う重量を挙げた場合は、実際に挙げた重量を書く。

================================================================================
 4. 骨格推定（YOLO26）
================================================================================

      python scripts\pose_extract_yolo.py --subject S001

  1本あたり数十秒〜数分かかる（GPUがあれば速い）。

  出力先: data\S001\SES004\pose\
      set01_yolo_keypoints.csv   … 17関節 × 全フレームの座標
      set01_yolo_features.csv    … 関節角度・体幹傾き等
      set01_yolo_annotated.mp4   … 骨格を重ねた確認用動画
      set01_yolo_plots.png       … 角度の時系列プロット

  ■ 処理済みを再処理したいとき

      python scripts\pose_extract_yolo.py --subject S001 --force

  ■ 速く回したいとき（動画とプロットを出さない）

      python scripts\pose_extract_yolo.py --subject S001 --no-video --no-plot

  ■ MediaPipe と比較したいとき

      python scripts\pose_extract.py --subject S001
      python scripts\compare_pose_models.py --subject S001

================================================================================
 5. バーベル軌道の抽出（任意）
================================================================================

      python scripts\bar_path_extract.py --subject S001

  初回はプレートの位置（ROI）を指定する画面が出る。
  検出したROIは保存されるので、2回目以降は自動で再利用される。

  出力: set01_bar_path.csv, set01_bar_summary.json など

================================================================================
 6. 特徴量抽出
================================================================================

      python scripts\extract_features.py --subject S001

  1試技 → 特徴量ベクトル1件（JSON）に変換する。

  出力: data\S001\SES004\features\set01_features.json

  実行すると、こう表示される:

      [RUN] S001/SES004/imu/set01_BAR.csv (set_no=1)
        rpe=7.0, weight=130, reps_detected=3, peak_v=0.445

  ここで peak_v（ピーク速度）が 0.3〜1.5 m/s の範囲なら正常。
  数 m/s など極端な値なら、IMUの向きか積分処理を疑う。

================================================================================
 7. 全試技を1つの表にまとめる
================================================================================

      python scripts\aggregate_features.py

  出力: outputs\features_all.csv

  実行すると RPE の分布が表示される:

      [OK] saved: ...\outputs\features_all.csv
           rows: 12, cols: 36
           RPE distribution:
             RPE 7.0: 4
             RPE 8.0: 3
             RPE 9.0: 5

  → RPE が特定の値に偏っていないか確認する。
    偏っていたら、次回のセッションで別の負荷帯を狙う。

================================================================================
 8. モデルの学習（データが溜まってから）
================================================================================

  目安として 30試技以上 集まってから実行する。
  それ未満だと評価が成立しない。

      python scripts\train_rpe_model.py

  出力: models\<タイムスタンプ>\
      linear.pkl / rf.pkl / gb.pkl     … 学習済みモデル
      metrics.json                     … 評価結果
      scatter_*.png                    … 予測 vs 実測
      importance_*.png                 … 特徴量重要度

  ■ 学習済みモデルで予測を試す

      python scripts\predict_rpe.py --latest

================================================================================
 確認ポイント（毎回チェックする）
================================================================================

  [1] session_info.json の mean_hz
      → 90〜100 なら正常。50を下回るならWi-Fiが弱い。

  [2] extract_features.py の peak_v
      → 0.3〜1.5 m/s が妥当な範囲。

  [3] pose\*_yolo_annotated.mp4
      → 最深部でも骨格が崩れていないか目視で確認。

  [4] pose\*_yolo_features.csv の key_visibility
      → 0.7以上を保っていれば良好。

  [5] RPE と peak_v の関係
      → RPEが高いほど速度が遅い、という傾向が出ていればOK。

================================================================================
 トラブル
================================================================================

  ■ [INFO] no videos found と出る

    動画の置き場所を確認する。以下のどちらでもよい。
        data\<被験者>\<セッション>\videos\*.mp4
        data\<任意フォルダ>\<任意フォルダ>\*.mp4

    --subject には、data\ の直下のフォルダ名を指定する。
        例: data\_sessions\... を処理  → --subject _sessions
            data\S001\...     を処理  → --subject S001

  ■ markers.csv がありません と出る

    受信スクリプトを正常終了（q キー）していない可能性がある。
    強制終了した場合、markers.csv が書き出されない。
    raw_*.csv は残っているので、markers.csv を手で作れば復旧できる。

        set_no,start_s,end_s,duration_s,rpe
        1,21.3,26.8,5.5,7.0

  ■ rpe が空欄のまま

    計測時に数字キーを押し忘れている。
    markers.csv の rpe 列に手で書き込めばよい。

  ■ 特徴量に NaN が多い

    IMUの取りこぼしか、骨格推定の失敗。
    session_info.json の mean_hz と、pose の key_visibility を確認する。
